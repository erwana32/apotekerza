# 0006. POS is online-first and open to offline

- **Status:** Accepted
- **Date:** 2026-11-24

## Context

A pharmacy may lose internet. Full offline POS adds sync and stock-conflict complexity that version 1 does not need.

## Decision

Version 1 is online-only (one VPS, accepted risk). The contract is prepared for offline: draft IDs are generated by the client (UUIDv7), every sale carries a `client_request_id` for idempotency, both `client_created_at` and `created_at` (server) are stored, and the invoice number is assigned by the server when the sale is posted.

## Consequences

- If connectivity proves unreliable, two options remain: a local server at the pharmacy, or an offline POS using the idempotency key and client timestamps.
- Cashiers cannot sell while the internet is down in version 1.

## Alternatives considered

- **Offline-first POS now:** large added complexity (sync, conflicts, stock) before the core flow is proven.
